# 规划前问答

在制定线路前一次问完。用户已提供的字段不要重复问。

## 推荐问法

```text
先确认几项，我再开始排线路和生成网页：

1. 从哪里出发？可以填多个城市，例如“上海或北京”。
2. 想去哪里？请写国家/城市；还没定城市也可以让我推荐。
3. 想要哪种节奏？
   - 休闲游：每天 1–2 个核心地点，有自由时间
   - 均衡游：每天 2–3 个核心地点
   - 特种兵：每天 3–5 个地点，早出晚归
4. 有没有必须去的景点？没有就写“没有”。
5. 预算大约多少？请说明按人/总计、币种、是否包含国际机票。
6. 日期或月份、总天数？
7. 几个人？有儿童吗？住宿几间房？
8. 签证情况？（出境游必问）持什么护照、是否已有签证/免签/落地签、旅游还是探亲/商务？

可选补充：忌口、购物、徒步、夜生活、酒店档次等。
```

## 有结构化提问工具时

优先一次展示多题：

- 出发地：自由输入；允许“上海、北京”这种多值
- 目的地：自由输入
- 节奏：`休闲游` / `均衡游` / `特种兵`
- 必去景点：自由输入 / `没有`
- 预算：自由输入，必须明确按人或总计、是否含机票
- 日期 / 天数：自由输入
- 同行人：自由输入
- 签证：持照身份 / 已有签证或免签情况 / 出行目的（出境游显示）

## 签证如何落到网页

出境游在确认摘要后写入 `visa`（详见 [reference.md](reference.md)）：

| 用户说法 | `visa.status` | 页面表现 |
|----------|---------------|----------|
| 还没办 / 要办旅游签 | `required` | 完整清单 + 官网入口 + 建议办理时间 |
| 免签 / 过境免签 | `visa_free` | 简短说明停留条件与注意事项 |
| 落地签 | `on_arrival` | 落地材料与费用提醒 |
| ETA / 电子旅行许可 | `eta` | 在线申请入口与有效期提醒 |
| 已有有效签证 | `already_have` | 核对有效期与入境次数即可 |
| 纯国内游 | 省略或 `not_needed` | 不展示签证块 |

规则：

- 只写「怎么办、准备什么、去哪申请」，不代填签证表、不承诺获批。
- 费用写进 `budget.extras`（`cat: "other"`），金额标注「以官网为准」。
- 页面 checklist 勾选状态只存在本机浏览器，不上传护照号或申请号。

## 解释预算

若用户只说“预算 1 万”，追问：

1. 每人还是所有人合计？
2. 是否包含往返机票？
3. 使用人民币还是当地货币？

网页总览以**每人预算**为主；若用户给的是总预算，先按人数换算，并在 `budget.basis` 写明。

## 必去景点约束

- 必去点必须进入 `days[].items[]`。
- 先按地理位置、开放时间和预约要求安排。
- 若时间、季节或交通上不可行，先直接说明冲突，再给替代方案；不要悄悄删掉。

## 节奏如何落到行程

| 节奏 | 每日核心地点 | 建议 |
|------|--------------|------|
| 休闲游 | 1–2 | 同一区域、少换乘、保留半天或晚间自由活动 |
| 均衡游 | 2–3 | 同方向串联，避免跨城折返 |
| 特种兵 | 3–5 | 标出早出晚归和交通风险，仍需留吃饭与转场时间 |

餐厅、酒店和交通节点不计入“核心地点”数量。

## 出发地如何落到网页

```js
budget: {
  origins: [
    {
      id: "shanghai",
      label: "上海",
      cny: 3200,
      brief: "去回航班与时间摘要",
      note: "估价依据与注意事项",
      adjust: []
    },
    {
      id: "beijing",
      label: "北京",
      cny: 3800,
      brief: "去回航班与时间摘要",
      note: "估价依据与注意事项",
      adjust: []
    }
  ]
}
```

有多个 `origins` 时，预算栏自动出现可点击切换；切换后总预算与航班说明必须变化。
